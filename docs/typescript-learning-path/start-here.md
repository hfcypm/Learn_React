# TypeScript 新手导读

## 适合谁

这套路线适合已经会写 JavaScript，准备为项目添加类型系统、降低大型应用维护成本的人。学习重点是理解 TypeScript 如何把"运行期错误"提前到"编译期发现"，再逐步掌握泛型、条件类型和类型安全工程实践。

## 开始前准备

- 能使用变量、函数、对象、数组和 Promise。
- 能理解作用域、闭包和模块导入。
- 能使用终端、npm 和编辑器。
- 安装受支持的 Node.js LTS 和 TypeScript。

```bash
node --version
npm --version
npx tsc --version
```

## 学习顺序

| 阶段 | 先回答的问题 | 阶段产出 |
| --- | --- | --- |
| 零 | TypeScript 解决什么问题，如何编译和运行？ | 配置好的最小项目 |
| 一 | 如何用接口、类型别名和函数类型建模数据？ | 类型安全的工具函数 |
| 二 | 泛型如何提升复用，条件类型和映射类型如何工作？ | 可复用的通用类型 |
| 三 | 声明文件、模块系统和工具类型如何支撑工程？ | 声明文件与迁移计划 |
| 四 | 如何在 React 中落地类型安全？ | 类型安全的组件与 API 层 |

## 每阶段学习方法

1. 先理解"编译边界"：哪些检查发生在编译期，哪些在运行期。
2. 每个概念先用最小示例跑通，再放进综合项目。
3. 主动制造一次类型错误，阅读编译器给出的错误信息。
4. 完成阶段项目增量，再进入下一阶段。

## 常见排错顺序

```text
TypeScript 版本
  -> tsconfig 配置（strict、module、lib）
  -> 模块解析与导入形式
  -> 类型推导是否符合预期
  -> 类型断言与 any 的扩散
  -> 编辑器、测试和构建工具的一致性
```

## 阶段项目路线

从 [综合实战](./project-practice.md) 开始，逐步把 JavaScript 代码迁移到 strict TypeScript，覆盖数据建模、API 类型安全、异步状态和工程配置。类型检查作为每次变更后的门禁。

## 完成标准

- 能解释类型推导、类型注解和类型断言的差异。
- 能使用泛型、条件类型和映射类型解决真实复用问题。
- 能编写声明文件并完成 JavaScript 到 strict TypeScript 的迁移计划。
- 能在 React 中完成类型安全的组件、表单和 API 层。
- 完成 [学习评估](./learning-assessment.md) 中的阶段考核与项目评分。
