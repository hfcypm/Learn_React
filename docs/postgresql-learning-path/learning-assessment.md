# PostgreSQL 学习评估与项目评分

**目标**：通过概念、编码、排错和项目评审确认学习者是否真正掌握了 PostgreSQL 的关系模型、SQL、数据建模、事务、索引和生产运维，避免只记住语法。

## 1. 阶段考核

### 阶段零：数据库基础与工具链

- 解释关系模型中的表、行、主键、外键和索引。
- 安装并连接 PostgreSQL，使用 psql 完成建库建表。
- 解释连接串各部分的含义。

### 阶段一：核心 SQL 与查询

- 写过滤、排序、分页查询。
- 正确使用四种 JOIN 连接类型。
- 用聚合与 GROUP BY、HAVING 完成统计。
- 用窗口函数解决排名和累计问题。

### 阶段二：数据建模与约束

- 设计范式合理、约束完整的数据模型。
- 实现一对一、一对多、多对多关系。
- 选择并创建合适的索引类型。

### 阶段三：事务、锁与性能优化

- 解释四种隔离级别及各自解决的问题。
- 用事务和 `FOR UPDATE` 处理并发场景。
- 用 EXPLAIN ANALYZE 定位慢查询并优化。

### 阶段四：生产运维

- 用 pg_dump 与 WAL 归档完成备份和恢复。
- 配置流复制并理解高可用方案。
- 用系统视图监控连接、慢查询和膨胀。

## 2. 排错题

- 连接被拒绝或权限错误。
- 字符串比较大小写敏感。
- JOIN 后行数变多产生重复。
- GROUP BY 报错。
- 索引未被使用。
- 查询阻塞或死锁。
- 表膨胀严重。
- 备份恢复失败。
- 隔离级别冲突。

## 3. 项目评分

总分 100 分，70 分通过，90 分优秀。参考 [综合实战：电商订单数据库](./project-practice.md)：

| 维度 | 分值 | 评分重点 |
|---|---:|---|
| 数据建模 | 20 | 范式、约束、关系完整性 |
| SQL 能力 | 20 | JOIN、聚合、窗口函数正确性 |
| 索引设计 | 20 | 索引选择、组合列顺序、验证 |
| 事务与并发 | 20 | 隔离级别、锁、幂等设计 |
| 性能优化 | 10 | EXPLAIN 使用、慢查询处理 |
| 运维能力 | 10 | 备份恢复、监控完整性 |

## 4. 项目评审问题

- 为什么选择这个主键方案，自增还是 UUID？
- 如何保证并发下不超卖？
- 复合索引的列顺序如何决定？
- 什么时候用 JSONB 而非新建表？
- 如何判断一个查询是否需要索引？
- 事务隔离级别如何选择？
- 备份策略如何设计，RTO 和 RPO 是多少？
- 表膨胀如何发现和治理？
- 如何定位并解决锁等待？
