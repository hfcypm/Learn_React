# React 学习评估与项目评分

**目标**：用可观察的结果判断学习者是否掌握能力，避免只完成阅读和勾选清单。

## 1. 四类评估

| 类型 | 目的 | 示例 |
|---|---|---|
| 概念题 | 检查原理理解 | 解释闭包、key、Effect 生命周期 |
| 编码题 | 检查独立实现能力 | 完成表单、分页、Hook 或 reducer |
| 排错题 | 检查诊断能力 | 处理竞态、重复渲染、401、构建失败 |
| 项目题 | 检查工程交付能力 | 完成带测试、权限和部署的应用 |

## 2. 阶段考核

### 阶段零

- 解释事件循环和 Promise 执行顺序。
- 完成带取消和错误处理的 API 请求。
- 使用浏览器工具定位一次请求失败。
- 提交一个可复现的原生 JavaScript 小项目。

### 阶段一

- 完成 TodoList、登录页或列表页。
- 正确处理 Props、state、列表 key、表单和事件。
- 覆盖 loading、empty、error 三种基础 UI 状态。

### 阶段二

- 编写一个自定义 Hook。
- 使用 reducer 管理复杂表单或购物车状态。
- 配置路由、嵌套路由和权限入口。
- 使用 Profiler 解释一次无效重渲染。

### 阶段三

- 使用 TypeScript 严格模式完成业务模块。
- 使用服务端状态库实现缓存和失效。
- 完成 API client、错误模型和表单 schema。
- 配置 lint、类型检查、测试和构建。

### 阶段四

- 解释 Render、Commit、Fiber 和调和过程。
- 完成代码分割、大列表优化和性能测量。
- 设计 SSR/SSG/RSC 的适用场景。
- 完成测试、部署、监控和回滚方案。

## 3. 排错题模板

每道排错题都应包含：

1. 最小复现代码或错误日志。
2. 预期行为和实际行为。
3. 可能影响的用户场景。
4. 分层排查路径。
5. 修复方案和回归测试。

推荐题型：

- Effect 依赖缺失导致数据过期。
- 请求返回顺序错误导致旧数据覆盖新数据。
- 列表使用 index 作为 key 造成状态错位。
- Context value 引用变化造成大范围重渲染。
- 401 刷新流程造成请求循环。
- 生产环境深链接刷新返回 404。
- 组件测试依赖实现细节导致重构后大量失败。

## 4. 项目评分表

总分 100 分，建议 70 分作为阶段通过线，90 分以上作为优秀项目。

| 维度 | 分值 | 评分重点 |
|---|---:|---|
| 功能完整性 | 20 | 核心流程、边界状态、错误恢复 |
| React 能力 | 15 | 组件边界、Hooks、状态建模、渲染理解 |
| TypeScript | 15 | 数据模型、Props、API、运行时校验 |
| 架构设计 | 15 | 模块边界、依赖方向、复用和扩展 |
| 测试质量 | 15 | 单元、组件、集成、E2E 的有效性 |
| 性能体验 | 10 | 加载、交互、列表、包体积和指标 |
| 安全可访问性 | 5 | 权限、输入处理、键盘和语义化 |
| 工程交付 | 5 | lint、构建、CI、文档和回滚 |

## 5. 评审问题

项目评审时要求学习者回答：

- 为什么这个状态放在组件、Context 或服务端状态库中？
- 失败、重试、取消和重复提交如何处理？
- 哪些逻辑有测试，哪些逻辑暂时没有测试？
- 如何证明性能优化有效？
- 权限校验在哪里完成？前端隐藏按钮解决了什么问题？
- 如果接口字段变化，哪些代码会先暴露问题？
- 如何发布、监控和回滚这个项目？
