# 综合实战：企业级 React 中后台

**目标**：用一个完整项目串联 React、TypeScript、路由、服务端状态、权限、测试、性能和交付能力。

## 1. 项目范围

构建一个“团队成员管理系统”，包含登录、成员列表、成员详情、角色权限、筛选分页和审计记录。

### 页面清单

- 登录页
- 首页仪表盘
- 成员列表页
- 成员创建与编辑页
- 成员详情页
- 角色与权限页
- 审计日志页
- 403、404、500 和通用错误页

## 2. 技术约束

- React + TypeScript 严格模式
- Vite 或 Next.js，项目启动时明确渲染模式
- React Router 或 Next.js App Router
- TanStack Query 或 RTK Query 管理服务端状态
- React Hook Form + Zod 管理复杂表单
- Vitest + React Testing Library
- Playwright + MSW
- ESLint + Prettier
- CI 自动执行检查和构建

## 3. 数据模型

```ts
type Role = 'admin' | 'manager' | 'member';

type User = {
```

## 4. 功能要求

### 登录与会话

- 登录成功后进入首页。
- 未登录访问业务页时跳转登录页。
- 会话过期时清理用户信息并提示重新登录。
- 401、403 分别进入会话恢复和无权限流程。
- 退出登录清理客户端缓存和敏感状态。

### 成员列表

- 支持关键词、角色、状态和创建时间筛选。
- 筛选条件同步到 URL。
- 支持服务端分页、排序和缓存。
- 支持加载、空数据、错误和重试状态。
- 删除操作要求确认，并在失败时恢复列表。

### 成员表单

- 姓名、邮箱、角色和状态具备类型化校验。
- 邮箱使用客户端和服务端双重校验。
- 提交期间禁用重复提交。
- 服务端字段错误显示在对应输入框旁。
- 离开未保存页面时给出提示。

### 权限

使用权限矩阵描述页面与操作：

| 操作 | admin | manager | member |
|---|---:|---:|---:|
| 查看成员 | 是 | 是 | 只读 |
| 创建成员 | 是 | 是 | 否 |
| 编辑成员 | 是 | 是 | 否 |
| 删除成员 | 是 | 否 | 否 |
| 查看审计日志 | 是 | 是 | 否 |

前端根据权限隐藏或禁用入口，服务端对每个 API 重新校验权限。

## 6. 测试验收

### 单元测试

- 权限判断函数覆盖所有角色和边界权限。
- 分页参数转换覆盖空筛选和非法参数。
- 表单 schema 覆盖必填、格式和长度限制。
- reducer 或状态转换覆盖成功、失败和重置。

### 组件测试

- 登录成功、失败和重复提交。
- 列表加载、空数据、错误和重试。
- 表单校验、提交成功和服务端错误。
- 删除确认、取消和失败恢复。
- 键盘访问弹窗和表单。

### E2E 测试

- 用户登录后访问成员列表。
- 无权限用户访问受限操作。
- 创建成员并在列表中看到结果。
- 编辑成员后刷新页面仍保持正确数据。
- 删除失败时页面恢复原状态。

## 7. 性能验收

- 首屏核心页面具备明确 loading 和骨架屏。
- 成员列表使用服务端分页或虚拟化。
- 路由级代码分割生效。
- 不在渲染路径中执行无必要的大量计算。
- 生产构建后使用 Bundle Analyzer 检查主要依赖。
- 记录 LCP、CLS、INP 等核心指标。

## 8. 生产验收

- `lint`、类型检查、测试和构建全部通过。
- 生产环境变量通过部署平台注入。
- 错误监控包含版本、路由和 request ID。
- 关键 API 有超时、取消、重试和错误转换。
- 权限校验在服务端完成。
- 发布制品可追溯，具备回滚步骤。
- README 包含启动、测试、构建和部署命令。

## 9. 阶段成果

完成项目后，学习者应能够：

- 设计合理的 React 模块边界。
- 区分客户端状态、服务端状态、表单状态和 URL 状态。
- 为异步页面设计完整状态机。
- 编写用户行为导向的测试。
- 处理鉴权、权限、错误、可访问性和性能问题。
- 通过 CI 交付可验证的生产构建产物。
