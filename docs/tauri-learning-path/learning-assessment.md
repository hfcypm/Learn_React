# Tauri 学习评估与项目评分

**目标**：通过概念、编码、排错和项目评审确认学习者是否真正掌握了 Tauri 2 的架构、命令、权限与打包发布，避免只记住 API 名称。

## 1. 阶段考核

### 阶段零：基础与工具链

- 解释前端、Rust 后端与系统 WebView 的关系。
- 初始化项目并运行窗口。
- 读懂 tauri.conf.json 的核心字段。

### 阶段一：配置与权限

- 解释 capabilities 与 permissions 的作用。
- 为插件声明最小权限。
- 按窗口拆分能力文件。

### 阶段二：Rust 命令与后端

- 定义并注册命令。
- 序列化复杂参数与返回值。
- 用 `Result` 传递错误。
- 用 `State` + `Mutex` 共享状态。

### 阶段三：系统能力与插件

- 用事件实现前后端通知。
- 安装并配置官方插件。
- 用文件系统与对话框插件完成交互。

### 阶段四：打包发布与生产

- 打包跨平台产物。
- 配置签名与更新机制。
- 按最小权限与安全基线审查应用。

## 2. 排错题

- Rust 工具链与系统依赖缺失。
- 编译错误与 Cargo 依赖。
- 命令未注册或参数不匹配。
- 权限未声明导致调用被拒。
- 事件名不匹配。
- 路径拼接错误或穿越。
- 插件未注册或未声明权限。
- 打包缺少图标或依赖。
- 更新失败（公钥、端点、签名产物）。

## 3. 项目评分

总分 100 分，70 分通过，90 分优秀。参考 [综合实战：跨平台文件管理器](./project-practice.md)：

| 维度 | 分值 | 评分重点 |
|---|---:|---|
| 命令与后端 | 25 | 命令设计、序列化、状态、错误处理 |
| 权限与安全 | 20 | 最小权限、路径过滤、CSP |
| 系统能力 | 20 | 文件、对话框、事件、插件使用 |
| 前端集成 | 15 | invoke 类型安全、状态刷新、交互 |
| 工程化 | 20 | 打包、签名、更新、发布清单 |

## 4. 项目评审问题

- 前端与 Rust 后端如何协作？invoke 与事件各自的使用边界？
- 为什么 Tauri 2 把权限做成显式声明？
- 如何为多窗口设计独立的能力文件？
- 命令的参数如何保证类型安全与输入校验？
- 什么时候用插件，什么时候自定义命令？
- 如何防止路径穿越与危险文件操作？
- Tauri 相比 Electron 的体积、性能与安全优势在哪里？
- 更新机制如何保证包的完整性与真实性？
- 如何权衡移动端支持与桌面端特性？
