# Next.js 学习评估与项目评分

**目标**：通过概念、编码、排错和项目评审确认学习者是否真正掌握了 Next.js 路由、渲染、数据获取、鉴权和生产交付，避免只完成阅读和勾选清单。

## 1. 阶段考核

### 阶段零：基础与项目初始化

- 解释 App Router 中 `layout.tsx` 和 `page.tsx` 的作用。
- 使用 `create-next-app` 创建项目并启动开发服务器。
- 解释环境变量 `NEXT_PUBLIC_` 前缀的意义。
- 理解 `npm run build` 输出的路由渲染标记。

### 阶段一：App Router 路由与渲染

- 创建嵌套路由、动态路由和捕获路由。
- 解释 Server Component 与 Client Component 的区别。
- 配置 layout、loading、error 和 not-found 边界。
- 使用 `generateMetadata` 生成动态 SEO 元数据。

### 阶段二：数据获取、缓存与重新验证

- 解释静态渲染、动态渲染和 ISR 的差异与适用场景。
- 使用 `revalidatePath` 和 `revalidateTag` 失效缓存。
- 编写 Route Handlers 并处理参数、错误和状态码。
- 判断何时用 Server Component 获取数据、何时用客户端数据层。

### 阶段三：Server Actions、表单与鉴权

- 使用 Server Actions 完成创建、更新和删除。
- 在服务端校验输入并回传字段错误。
- 实现登录、会话 Cookie 和退出。
- 在 Server Action 中完成鉴权和资源归属校验。

### 阶段四：性能、工程化与生产交付

- 使用 `next/image`、`next/font` 和动态导入优化性能。
- 编写单元、组件和 E2E 测试。
- 配置安全响应头、CORS 和环境变量校验。
- 完成生产构建、部署和回滚验收。

## 2. 排错题

- 点击链接整页刷新而非客户端导航。
- 页面数据长期不更新，缓存未失效。
- Server Action 校验不生效，输入被浏览器绕过。
- 未登录用户直接访问受保护页面。
- 权限检查放在前端隐藏按钮但服务端未校验。
- `params` 为 undefined 或类型错误。
- 发布文章后列表不刷新。
- 生产构建与环境变量缺失导致失败。
- 首屏 JavaScript 过大拖慢加载。

## 3. 项目评分

总分 100 分，70 分通过，90 分优秀。参考 [综合实战：内容平台](./project-practice.md)：

| 维度 | 分值 | 评分重点 |
|---|---:|---|
| 功能完整性 | 20 | 列表、详情、登录、发布、编辑、删除 |
| 路由与渲染 | 15 | App Router、Server/Client 组件边界 |
| 数据与缓存 | 15 | 数据获取位置、ISR、缓存失效 |
| 鉴权与安全 | 15 | 会话、权限、输入校验、安全响应头 |
| TypeScript | 10 | 类型模型、schema、泛型 |
| 测试质量 | 15 | 单元、组件、E2E 的有效性 |
| 工程交付 | 10 | lint、构建、部署、监控、回滚 |

## 4. 项目评审问题

- 为什么这个页面选择静态渲染、动态渲染或 ISR？
- Server/Client 组件边界如何划分，依据是什么？
- 数据请求放在服务端还是客户端，为什么？
- 缓存失效如何触发，`revalidatePath` 与 `revalidateTag` 有何区别？
- 权限校验在哪里完成？前端隐藏按钮解决了什么问题？
- 输入校验如何防止被浏览器端绕过？
- 如何证明性能优化有效？
- 如何发布、监控和回滚这个项目？
