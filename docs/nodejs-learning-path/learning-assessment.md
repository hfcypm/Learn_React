# Node.js 学习评估与项目评分

**目标**：通过概念、编码、排错和项目评审确认学习者是否真正掌握了 Node.js 服务端开发，避免只完成阅读和勾选清单。

## 1. 阶段考核

### 阶段零：运行时与 JavaScript 基础

- 解释事件循环、宏任务、微任务和 Promise 异常传播。
- 说明 `node:` 前缀、ESM 与 CommonJS 的差异。
- 完成一个带参数和错误处理的 CLI 脚本。
- 使用 `node --watch` 和调试器定位一次异步错误。

### 阶段一：Node.js 核心 API

- 用原生 `http` 模块完成带 `/health` 和 `/echo` 的服务。
- 解释 Stream、背压和 `fs` 同步/异步 API 的适用边界。
- 为请求体设置大小限制、超时和取消。
- 使用 `curl` 覆盖 GET、POST 和错误请求。

### 阶段二：Web 服务与数据层

- 分层组织 Controller、Service 和 Repository。
- 为外部输入完成校验、统一错误和分页。
- 完成用户 CRUD，覆盖校验失败、重复数据和未找到。
- 使用参数绑定 SQL，并完成一次事务与回滚。

### 阶段三：工程化与并发

- 为 Service 和 HTTP 核心流程编写 `node:test` 测试。
- 接入 request ID 结构化日志和配置校验。
- 解释主线程阻塞与 Worker 的边界，并测量一次阻塞影响。
- 实现优雅退出并验证 `kill -TERM` 行为。

### 阶段四：生产交付

- 配置安全响应头、CORS 白名单、限流和健康检查。
- 完成 Docker 镜像、数据库迁移和冒烟测试。
- 实现重试、退避、熔断或幂等键中的至少一项。
- 完成备份恢复和故障排障演练。

## 2. 排错题

- 事件循环被同步代码阻塞导致请求排队。
- `await` 使用在非 async 函数中导致语法错误。
- ESM 与 CommonJS 导入路径或扩展名不匹配。
- 请求体读取未处理 `end` 事件或超时。
- 路径参数未解码导致路径穿越风险。
- 未绑定参数导致 SQL 注入。
- 密码哈希明文写入数据库或日志。
- 进程收到 SIGTERM 时未完成优雅退出。
- 健康检查未区分存活与就绪导致流量进入未就绪实例。

## 3. 项目评分

总分 100 分，70 分通过，90 分优秀。参考 [综合实战：用户管理 API](./project-practice.md)：

| 维度 | 分值 | 评分重点 |
|---|---:|---|
| 功能完整性 | 20 | 用户 CRUD、认证、分页、错误恢复 |
| HTTP 与运行时 | 15 | 请求生命周期、Stream、超时与取消 |
| 数据层 | 15 | 参数绑定、事务、迁移、审计 |
| 测试质量 | 15 | 单元、集成、HTTP 测试的有效性 |
| 工程化 | 15 | 配置校验、日志、健康检查、优雅退出 |
| 生产交付 | 10 | Docker、限流、备份恢复、回滚 |
| 安全 | 10 | 校验、密码、日志脱敏、CORS 白名单 |

## 4. 项目评审问题

- 一次请求从入口到数据库返回经历了哪些层？各层职责是什么？
- 输入校验、认证、授权、业务错误和基础设施错误如何区分？
- 哪些操作是阻塞的，为什么阻塞，如何避免？
- 数据库事务在什么情况下必须使用？
- 如何证明测试覆盖了核心业务，而不只是"跑通"？
- 生产环境如何注入配置、迁移数据库、检查就绪和优雅退出？
- 如果数据库连接失败，服务会怎样表现？
