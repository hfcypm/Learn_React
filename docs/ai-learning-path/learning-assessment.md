# AI 应用前端学习评估与项目评分

**目标**：通过概念、编码、排错和项目评审确认学习者是否真正掌握了 AI 应用前端的数据流、实时通信和内容渲染，避免只完成阅读和勾选清单。

## 1. 阶段考核

### 阶段一：TanStack Query

- 解释服务端状态与客户端状态的区别。
- 完成带加载、空数据、失败和取消状态的查询。
- 使用变更（mutation）并处理失效、重试和乐观更新。
- 说明缓存 key 设计如何影响一致性与请求次数。

### 阶段二：Zustand

- 设计 Store 的状态、动作和选择器边界。
- 处理会话、草稿和跨组件共享状态。
- 说明哪些状态属于组件、哪些属于全局 Store、哪些属于 URL。
- 完成一个带持久化和清理逻辑的 Store。

### 阶段三：实时与流式响应

- 区分 SSE、WebSocket 和 fetch 流式响应的适用边界。
- 实现逐字流式回答、停止生成、重试和错误恢复。
- 处理取消、超时和连接断开后的恢复。
- 解释流式 UI 如何避免旧数据覆盖新数据。

### 阶段四：内容渲染

- 安全处理文件上传，校验类型和大小。
- 渲染 Markdown、GFM 表格、代码高亮和图表。
- 处理服务端返回的富文本与脚本内容的风险。
- 完成至少一个渲染组件的错误与空数据状态。

## 2. 排错题

- 流式响应在 UI 上不逐字更新。
- 停止生成后请求仍在继续或被缓存。
- 旧请求返回后覆盖新请求的显示结果。
- Query 缓存导致数据长期不刷新。
- Store 状态与组件本地状态重复导致不一致。
- WebSocket 断开后未自动重连或重复订阅。
- Markdown 渲染被注入脚本。
- 文件上传未校验类型、大小或重复提交。
- 401 或 429 后流式连接未正确恢复。

## 3. 项目评分

总分 100 分，70 分通过，90 分优秀。参考 [AI 学习工作台综合案例](./project-practice.md)：

| 维度 | 分值 | 评分重点 |
|---|---:|---|
| 功能完整性 | 20 | 会话、流式回答、停止、重试、文件上传 |
| 数据流 | 20 | 服务端/客户端/URL 状态边界 |
| 实时通信 | 20 | 流式读取、取消、重连、错误恢复 |
| 内容渲染 | 15 | Markdown、代码、图表、富文本安全 |
| TypeScript | 10 | 类型模型、schema 校验、泛型 |
| 测试质量 | 10 | 数据流、状态、渲染组件的有效性 |
| 工程交付 | 5 | lint、构建、环境变量、Mock 边界 |

## 4. 项目评审问题

- 会话、草稿和 AI 回答分别属于哪种状态，为什么？
- 流式回答如何防止旧数据覆盖新数据？
- 停止生成、重试和错误恢复如何设计？
- 服务端返回内容如何安全渲染？
- 文件上传校验在哪里完成，失败如何恢复？
- 如果后端从 Mock 换成真实服务，哪些代码需要改动？
- 如何验证缓存失效、连接断开和 429 场景？
